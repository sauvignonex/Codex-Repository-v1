## Результат

Панель на русском языке, которая создаёт оформленные анимированные субтитры в стиле ролика «Рилс Колобки». Результат должен допускать ручное редактирование текста, таймингов, шрифтов, цвета, размера, положения и анимации.

## Входные данные

- Готовые субтитры: SRT; возможность чтения captions непосредственно из последовательности проверить отдельно.
- Голос или аудио с последующим распознаванием на русском языке.
- Необязательный сценарий для исправления распознавания, имён и специальных слов.
- Исходный проект, видеообразец, тестовый фрагмент и PNG безопасной зоны предоставлены.
- Анимация текста в образце построена на готовых MOGRT с ручной подгонкой. Animation Composer использовался для шейповой анимации в шаблоне.
- Пользователь одобрил использование установленных наборов Reels Text Animation и SaaS Text Animation. В библиотеке найдены 28 Reels Text Animation и 18 SaaS Pack Title. Использовать подходящие шаблоны после проверки анимации, смены шрифта, длительности и безопасной зоны; параметры и пути сохранены в template-inventory.json.

## Текст и синхронизация

- До двух строк на экране.
- Порог 10 символов и минимум 2 секунды не являются требованиями.
- Короткие блоки из 1–2 слов оформляются крупнее шрифтом Bebas.
- Длинные блоки оформляются меньшим размером Cera Pro Medium.
- Christopher Regular используется для редких смысловых акцентов. По установленным файлам проверены названия Bebas Neue Cyrillic Regular, Cera Pro Medium и Christopher Regular; все поддерживают русские буквы, включая Ё.
- Плагин самостоятельно выбирает разбиение и стиль; пользователь может переопределить результат.
- В ролике обычные небольшие субтитры чередуются с крупными смысловыми заголовками. Выбор оформления должен учитывать роль текста, а не только число слов. Пользователь одобрил создание смысловых заголовков отдельной кнопкой с обработкой прямо из плагина.
- Предусмотреть режим следования фактической речи и режим сверки со сценарием. Не добавлять отсутствующие в речи фрагменты автоматически без обозначения расхождений.
- При исправлении без переразбиения сохранять границы исходных субтитров. При переразбиении получать новые границы из аудио или таймингов слов; не выдавать пропорциональное деление времени за точную синхронизацию.

## Размещение

- Соблюдать чёрную область пользовательского PNG, включая нижний правый вырез.
- Учитывать границы букв, обводку, тень и весь путь анимации.
- Подбирать переносы и размер, сохранять читаемость. При невозможности вместить блок — разбивать его, а не бесконечно уменьшать шрифт.
- Масштабировать координаты зоны под размер последовательности. Поведение при другом соотношении сторон согласовать отдельно.
- Показывать безопасную зону в предпросмотре; не включать её в конечное видео.

## Интерфейс

- Визуально аккуратная и понятная русскоязычная панель, согласованная с интерфейсом Premiere.
- Основной путь: источник → проверка текста → оформление → создание на таймлайне.
- Живой предпросмотр, короткий и длинный пример, воспроизведение анимации.
- Дополнительные настройки раскрываются по необходимости.
- Пользователь может менять любой выбранный автоматически стиль.
- Кнопка «Смысловые заголовки» запускает обработку выбранного фрагмента речи или текста. Предложения доступны для просмотра и правки перед созданием графики. Дословное оформление остаётся доступным.
- Понятные статусы: обработка, результат, необходимость исправления. Ошибки не скрывать за сообщением об успехе.

## Работа с агентом

Пользователь хочет возможность автоматически передавать голос или звук агенту для обработки. Это требование к будущей интеграции. Канал связи, доступные API, учётные данные, стоимость и возврат результата в Premiere ещё не определены. Наличие чата само по себе не подтверждает такую интеграцию.

12 октября пользователь подтвердил: смысловые заголовки должны создаваться в связке с ИИ прямо из панели, без ручного переноса данных в чат. Поток: выбранный фрагмент → отправка текста или аудио → получение предложений → просмотр и правка → создание графики с привязкой к исходному фрагменту. Исходная расшифровка сохраняется отдельно. Заголовок не должен добавлять факты, которых нет в исходном материале. Сохраняется привязка к исходным сегментам и их времени. Подключение ИИ ещё не реализовано; во второй версии макета есть явно обозначенная демонстрация на готовом примере.

## Проверка первого прототипа

1. Выбрать из проекта короткий и длинный текстовые блоки, изучить их оформление и анимацию.
2. Проверить установку панели и программную работу с редактируемой графикой в указанной сборке Premiere.
3. Создать несколько блоков из готового SRT с двумя шрифтами и подгонкой под безопасную зону.
4. Проверить ручную правку текста и параметров, сохранение проекта, повторное открытие и экспорт.
5. Сравнить результат с видеообразцом, затем расширить на весь фрагмент.
6. После проверки графики добавить исправление по сценарию, распознавание и интеграцию с агентом.

## Наблюдения по готовому ролику

Проверены кадры по всей длительности 68,63 секунды (1080×1920, 30 кадров/с), а также последовательности с шагом 0,1 секунды для трёх анимаций. Звуковая синхронизация на этом этапе не проверялась. Указанные ниже моменты приблизительные.

- 3–5 с: небольшая вводная строка «Уяча —» и крупная надпись «ВКУС МАРИЙ ЭЛ» ниже.
- 6–7 с и 54–57 с: небольшие белые фрагменты обычной речи в верхней части кадра.
- 16–18 с: «ФОРМА» появляется по буквам, затем отдельным этапом возникает меньшая строка «ПОЛНОЙ ЛУНЫ».
- 19–23 с: красный крупный заголовок «ПОЧЕМУ» и меньшая белая строка «РЖАНАЯ МУКА?».
- 23,5–25 с: рукописное «Угощение» появляется последовательно, затем возникает строка «для ряженых».
- 33–35 с: две строки разного размера — «ПРАВИЛО» и «НЕЧЁТНОГО ЧИСЛА».
- 38–43 с: небольшие белые субтитры на чёрной рисованной плашке в верхней части кадра.
- 50,7–52 с: жёлтый рукописный акцент «Обжарка», затем меньшая белая подпись «до золотистой корочки».
- 58–61 с: крупный вопрос «ТЮРКСКОЕ ВЛИЯНИЕ?» с меньшим уточнением «— одна из версий».

Для воспроизведения этого подхода нужны составные блоки с разными стилями строк и последовательностью появления. Автоматический выбор акцентов должен допускать исправление до создания графики.
